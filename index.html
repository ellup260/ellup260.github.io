Social Awareness Platform

A single-page application designed to raise awareness of social causes and help small businesses connect with their communities.

ReactExpress.jsMySQLCloud deployment
Explore project details

Project overview

The Social Awareness Platform is a full-stack single-page application designed to connect people with social causes and help small businesses reach their communities. Users can discover causes such as climate change and homelessness, browse by category or location, and find organisations and local services in one place.

The solution combines a React user interface, an Express.js REST API, a relational database, and cloud database/deployment planning. It also considers the administrative tools needed to keep content organised, review activity, and support platform governance.

Problem and purpose

Social initiatives and smaller businesses can struggle to reach the right audience. The platform aims to make information easier to discover by organising content around causes, categories, and locations, while giving registered users tools to manage their content.

My contribution

  • Contributed to project planning and translated requirements into application features and technical tasks.
  • Worked on relational database design for users, roles, login sessions, and password-reset workflows.
  • Contributed to the React frontend, Express.js backend structure, REST API integration, and MySQL data layer.
  • Designed requirements for a content management workflow so authorised users can create and maintain causes, business profiles, and promotional content.
  • Helped define an administrative analytics dashboard to give administrators a clearer view of platform activity, content, business registrations, and moderation needs.
  • Considered Google Cloud SQL as the managed relational database service, including connectivity, access, configuration, and deployment considerations.
  • Supported testing, troubleshooting, technical documentation, and cloud deployment preparation as part of the project team.

Approach and strategy

  • Start with user needs: identify the needs of content creators, organisations, businesses, visitors, and administrators.
  • Requirements first: map the needs of visitors, content creators, small businesses, and administrators before shaping features.
  • Modular architecture: separate authentication, cause discovery, business registration, advertising, content management, analytics, and administration so each area can be built and tested independently.
  • Data integrity: use relational tables and clear relationships for identity, roles, sessions, password resets, causes, and business records.
  • Managed cloud database: plan for Google Cloud SQL as the database service, with secure connectivity and controlled access rather than exposing database access publicly.
  • Incremental delivery: build and verify user journeys in small steps, test API behaviour with tools such as Postman, and troubleshoot issues using repeatable checks.
  • Security and reliability by design: consider role-based access, HTTPS, backups, performance, accessibility, and recovery requirements early.
  • Evidence-led handover: maintain setup instructions, database notes, test results, and deployment guidance so the solution can be understood and continued by others.

Key features and requirements considered

  • User registration, sign-in, profiles, and password reset.
  • Create and manage social causes, with category and location-based browsing.
  • Business registration, promotional listings, and business dashboards.
  • Content management workflows for creating and maintaining causes and business information.
  • Administrative analytics dashboard for reviewing platform activity and supporting moderation decisions.
  • Google Cloud SQL database planning and cloud deployment considerations.
  • Responsive design, access control, secure connections, backups, and test coverage.

Skills and lessons gained

  • Full-stack application architecture and frontend/backend integration.
  • Relational database modelling and thinking through data relationships.
  • Breaking broad requirements into smaller features and practical tasks.
  • Debugging integration problems and checking assumptions methodically.
  • Considering security, accessibility, reliability, and maintainability early.
  • REST API integration, endpoint testing, and structured troubleshooting.
  • Cloud database concepts, Google Cloud SQL connectivity, and deployment planning.
  • Thinking through content workflows, dashboard metrics, and admin-facing requirements.
  • Team communication, technical documentation, and practical handover planning.
